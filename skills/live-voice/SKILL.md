Tandem is the shared voice UI for Codex and Claude threads. Start it from the waveform next to dictation. Mute affects microphone capture. End closes voice while leaving submitted coding work running. Use BB’s thread controls to explicitly cancel agent work; completed actions are not undone. The voice controls expose mute and hang-up, without a separate Stop agent action.

Voice stays connected to its original thread during in-app navigation. On that thread, the waveform starts the call; live mute and circular red hang-up controls stay visible without an expansion stage. The live waveform is a noninteractive status indicator. Off-thread, a compact floating dial provides the same controls and a link back to the thread. Connected/unmuted waveforms pulse gently; detected assistant playback animates their bars and adds a glow. Muted silence is steady, while assistant playback can still glow with the mic muted. Both surfaces keep Mute and End visible; the live waveform has no toggle action. Composer controls fit the 36-pixel clipped action slot; floating controls are 44 pixels. Connecting calls expose End; disconnected calls expose Reconnect and End. Reduced-motion preferences suppress animation. The connected pulse is a state indicator, not a microphone-volume meter. Agent progress and briefing status are omitted from the call controls; connection and actionable error feedback remain. Starting voice elsewhere offers Switch call or Keep this call; switching ends only the old voice connection. One call per app window; server limits still apply across windows. Page exit/reload ends voice. Restarting makes a fresh realtime conversation using that thread's background policy, not restored audio-call memory. There is no pause/resume state.

The New thread waveform creates a visible thread with the selected project/environment and execution settings, waits up to two minutes for idle provider initialization, then connects voice. It requires BB's input-free initialization support (host protocol 271); older BB builds reject creation and need a core update. No placeholder task or draft text, mentions or attachments are submitted or cleared. Opening New thread creates nothing. Ending during setup blocks late navigation/connection, but a creation already sent may still finish. Inspect failed setup in the created thread and retry voice there. The SDK composer selection omits provider-specific option overrides and picker provenance; BB defaults apply to those fields.

Codex uses the existing native provider connection through BB’s threads.voice bridge. The plugin must not open another writer for that coding thread or re-execute native delegations. The local customized BB has the bridge; stock-BB native compatibility is not established. A missing bridge fails explicitly. Native handoff guidance is not call-scoped: in Codex 0.160.1 it is written into the coding thread's history during a call and stays there after hang-up, so a later call can inherit it until another turn intervenes. The proposed transport limits startup reference text to 16,000 characters and handoff guidance to 8,000. With the older threads.voice bridge, the native voice and handoff wording is owned by BB, not by this plugin.

Claude uses a temporary Codex app-server only to negotiate subscription-authenticated browser audio, then detaches it and delegates to the selected BB thread. It requires Codex ChatGPT sign-in on the BB server. Use codex login status without reading credentials. The executable setting can select the official CLI when a shell wrapper changes accounts. API keys and API billing fallback are unsupported. Audio relies on the negotiated connection surviving that detachment, which is observed rather than documented Codex behavior; re-verify after Codex upgrades.

Claude result delivery is event driven and incremental. A follow-up can steer voice-owned active work; unrelated active tasks are not silently queued or steered. A correction spoken before BB accepts the previous voice request waits up to 30 seconds for that request to be accepted or rejected, then steers the voice turn or starts a new one; if no answer arrives it fails clearly and leaves existing work running. BB's send API cannot target a specific turn, so steering depends on observed thread state and is not atomic. Tool approvals stay in BB. Raw reasoning and tool logs are not streamed as speech. Context instructions are agent-only, apply to voice requests, and are sent once after provider acceptance. New handoffs carry only new or corrected spoken turns. Existing historical wrappers remain unchanged.

Use bb plugin rpc inspect live-voice for available, start, stop, context, poll, delegate, and control schemas. start needs caller-supplied WebRTC SDP; poll supports afterSeq; control accepts cancelWork. While work runs, poll's attention state may reuse a pending-approval check for up to 2 seconds; a new approval request shows immediately. The CLI does not record or play voice.

Use bb plugin list and bb plugin logs live-voice for health. Rebuild with npm run check, npm test, and bb plugin build . before reload. Start a fresh call after upgrades. Do not claim exhaustive whole-thread coverage, general stock-BB compatibility, rollback of completed actions, or physical-device verification that has not happened.


Diagnostics default to basic, frozen per call: lifecycle/failure categories, connection/playback/mute, turn boundaries, startup cache metadata, and first/final delegation milestones. Basic excludes transcripts, exact context/request/result text, individual deltas and chunk timing before browser send and again at server ingestion. Use bb plugin config live-voice set diagnostics detailed for a fresh troubleshooting call, then restore basic. Detailed captures private text/timing; never raw audio/SDP/credentials/reasoning. Legacy full context can include source/tool material. No tracing path changes prompts, synthesis usage or endpointing.

traceSessions ({threadId?}) reports the frozen diagnostics policy; traceRead ({sessionId, afterId?:0}) pages with the last cursor until empty. trace accepts browser batches, not voice commands. Local plugin DB retention: 20 calls/seven days, 256,000 serialized bytes/basic call or 2,000,000/detailed, with 32,000 bytes reserved for stop/failure evidence. SQLite/index/WAL overhead and product briefings are additional. Existing detailed traces age out normally; no purge occurs. Warnings are rate-limited once/minute/call or browser collector. Dropped counts, truncation flags, browser sequence gaps and unsaved exit batches indicate incomplete evidence; server sequence is global, so per-call server gaps alone do not establish loss.

Startup records attempted cache state/age/fingerprint/length, with exact framing only in detailed mode. session.connect means negotiation succeeded; acknowledgements do not prove model attention and playback allowed does not prove physical output. Native observation cannot verify outgoing wire delivery. Claude detailed chunks correlate updateSeq; keep its functional streaming/poll/notifications. Basic native observation retains functional turn/state events but excludes diagnostic-only deltas. Browser elapsedMs is monotonic; server elapsedMs uses wall time. Compare fresh detailed calls with identical opening words and devices when diagnosing unsolicited responses.




The experimental Cached briefing boolean toggle (cachedBriefing, default false) supplies cached startup context. The old backgroundMode dropdown and deferred modes are retired. The plugin synthesizes structured goals, decisions, findings with source event pointers, and open questions using an isolated subscription-authenticated Codex session. Only fresh briefings enter initialItems before audio connects, on both adapters. The browser has no midcall append path; the legacy context RPC and poll backgroundContext remain for existing callers and always return null. A miss/stale/busy/error uses retrieval-only for the entire call and prepares the next call without waiting for a model at startup. Voice-used or explicitly prepared threads refresh when idle. Active work invalidates the cache. Source selection: latest 12 user requests and 100 root completed items after context clear, 60,000 characters total, 6,000 per item; includes tool results but excludes reasoning, nested agents and agent-only wrappers. Output is at most 3,000 JSON characters / 4,000 framed. Coverage is bounded, not exhaustive; synthesis can lose facts. One compiler job at a time, 90-second deadline, ChatGPT subscription only. Cache retention is 20 threads / seven days, freshness 24 hours plus matching semantic thread revision. Cached native calls additionally require startup-briefing bridge / host protocol 269. Do not silently downgrade missing native capabilities.

RPC briefingStatus, prepareBriefing and forgetBriefing accept {threadId}. Status returns missing/busy/preparing/ready/stale/error; only ready includes text. Prepare registers a watch and queues work when idle; it can explicitly prepare while background is off. Forget deletes cache and watch. Switching away from cached cancels pending synthesis. start returns optional briefing ready/lookup; context.startup records attempted cache metadata, adding the exact ready reference only in detailed mode. Briefing readiness stays available through RPC and diagnostics, without persistent call-control copy. Use bb plugin config live-voice set cachedBriefing true or false, then start a new call. Generated findings and transcripts are private local plugin data. Never equate injected context with guaranteed model attention or silent behavior.

## Voice selection

The Voice plugin setting applies to new Codex and Claude calls. Choose `default` to retain Codex’s configured/default voice (normally Cove), or `arbor`, `breeze`, `cove`, `ember`, `juniper`, `maple`, `sol`, `spruce`, or `vale`. These are the installed Codex v3 transport’s supported voices; the separate Realtime v2 catalog does not apply. Set it in plugin settings or with `bb plugin config live-voice set voice juniper`. End and start a fresh call to hear a change; changing the setting does not interrupt an existing call. Native Codex selection requires the customized BB voice-selection bridge (host protocol 270). Subscription authentication and delegation stay the same. Voice acceptance in a synthetic call does not verify device playback or perceived sound.

For the user-facing explanation of why Tandem is a plugin and which proposed changes belong in BB, read README.md and docs/maintainers.md. The plugin prefers threads.experimental_voice with caller-supplied initialContext, instructions and voice when present; the existing customized threads.voice path remains for the current installation. No second writer is opened. Proposed core PRs are not a stock-BB compatibility or deployment guarantee.
